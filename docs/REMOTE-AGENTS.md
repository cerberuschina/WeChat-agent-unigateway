# 非本机 agent 怎么接（远程接入）

网关仍然只在一台机器上守着那个真微信；**agent 可以跑在别的机器上**（另一台 Windows/Linux、
容器、甚至云主机）。差别只有三处：网络可达、取码要带密钥、媒体不能共用路径。

## 1. 网关侧：让它能被连上

```jsonc
"virtual": {
  "enabled": true,
  "host": "0.0.0.0",                          // 默认 127.0.0.1 = 只给本机
  "port": 18500,
  "bind_key": "<一段随机串>",                   // 远程 agent 取码必须带它
  "public_url": "http://192.168.1.5:18500",   // 远程 agent 用的下载地址用这个
  "auto_approve": []                          // 远程别自动放行：新接入一律人工批准
}
```

启动后日志里会多一行「远程接入已开启」；`http://127.0.0.1:18500/admin/binds` 仍是批准页
（它只监听本机，也就是只有你坐在网关那台机器上才能批准——这是故意的）。

## 1b. IPv6

`host` 直接支持 IPv6（服务端会按地址挑地址族，并对方括号做正确处理）：

```jsonc
"virtual": {
  "host": "::",                                      // 双栈：IPv4 与 IPv6 都能连
  "port": 18500,
  "bind_key": "<随机串>",
  "public_url": "http://[240e:3b7:1a2b::5]:18500"    // IPv6 字面量必须带方括号
}
```

- `host: "::1"` = 只收 IPv6 回环；`host: "::"` = 收全部（服务端设 `IPV6_V6ONLY=0` 做双栈，
  平台不允许该选项时自动退回 IPv6-only，不会启动失败）。
- **URL 里 IPv6 必须带方括号**：`http://[::1]:18500`。网关自己拼的链接（批准页、媒体下载地址）
  会自动加；你手写 `public_url` 时也要写对，否则链接点不开（测试里专门钉了这条）。
- 远程 agent：`--base-url http://[240e:3b7:1a2b::5]:18500`。
- 防火墙：Windows 首次监听会弹"允许访问"，或手动放行 18500/TCP；运营商给的 IPv6 前缀通常是
  `/64`，很多情况下公网可直连——**但那是明文 HTTP**。公网暴露前至少要 `bind_key` + 人工批准，
  更稳的是 SSH 隧道（见第 4 节）。IPv6 地址变化频繁，`public_url` 要跟着更新。

## 2. agent 侧：取码 → 批准 → 拿身份

```bash
python clients/ilink_agent_client.py --name claude \
    --base-url http://192.168.1.5:18500 \
    --bind-key "<同一段随机串>" \
    --runner "claude -p {text} --resume {session}"
```

1. 它取码（带 `bind_key`，没带的话网关直接拒绝：`errmsg` 会说清楚）；
2. 你在网关机器上批准并给它起名；
3. 它拿到虚拟号（`virt-claude…@im.bot`）+ token，之后长轮询、回话都和本机 agent 一样。

## 3. 媒体：不能靠路径，改走上传/下载

| 方向 | 本机 agent | 远程 agent |
|---|---|---|
| agent → 微信 | 递 `localpath:<绝对路径>`，网关自己读文件 | 客户端先把字节 POST 到 `/upload`（带 token），拿到 `blob:<id>` 再随消息发出 |
| 微信 → agent | 消息里给本地路径 | 消息里同时给「本地路径（网关所在机器）」和「下载地址」；客户端自动把下载地址取回本机，再把真实路径交给 agent（取不到就保留 URL 并在日志里说，不静默丢） |

`/upload` 与 `/media/<目录>/<文件名>` 都要虚拟身份 token；`/media` 会拒绝任何越出媒体根目录的路径。

## 4. 安全边界（请按这个判断要不要开）

- 默认 `host: 127.0.0.1`。改成 `0.0.0.0` 后协议是**明文 HTTP**——只适合可信局域网/内网。
- 跨不可信网络：用 **SSH 隧道**（`ssh -L 18500:127.0.0.1:18500 user@gateway-ip`，agent 侧照旧连
  `http://127.0.0.1:18500`）或**反向代理 + 真证书**（Caddy / nginx）。
- **故意没做内置自签 TLS**：那需要客户端信任自签证书，做一半比不做更危险（客户端会习惯性 `--insecure`）。
- `bind_key` 只挡"随手撞上来的人"；真正的门是**人工批准**。所以远程接入时 `auto_approve` 保持空。
- token 只发给批准过的 agent；网关不会把任何虚拟身份信息发往腾讯。

## 5. 目前不支持

- 跨机器的心跳：打字指示仍由网关按心跳（agent → 网关 `sendtyping`）维持，跨机器一路明文。
- 多网关 / 按 agent 隔离额度：额度账本是**按联系人**算的，与 agent 来自哪台机器无关。
- 断线续传：`/upload` 是整包上传，大文件目前一次吃完（几十 MB 级别没问题）。
